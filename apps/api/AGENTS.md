# @hrm/api

Ứng dụng NestJS duy nhất: config, health, authentication/session, authorization, administration, audit, database, các module nghiệp vụ trong `src/modules/` (ADR 0031) và fixture `document` (ADR 0032). Đọc root `AGENTS.md` trước; file này chỉ bổ sung phần riêng của app. ADR 0013 ghi việc gom bốn package vào app; không đổi hành vi quyền/dữ liệu.

## Ranh giới

- Logic phân quyền nằm trong `authorization/`; core thuần ở `authorization/core`, compiler/gateway và services ở cùng module. Không viết lại planner/compiler khi thêm feature; dùng implementation hiện có.
- Resource `document` (`document/document.declarations.ts`, `document/migrations/product-document.migration.ts`) chỉ là fixture của lõi phân quyền, không có route HTTP (ADR 0032); không xây domain demo lớn hoặc UI.
- Handler không nhận DataSource/QueryRunner/credential thô; truy cập dữ liệu chỉ qua gateway/command của adapter.
- Import boundary (developer, không phải process isolation): HTTP feature handlers không import driver, gateway/compiler, authority/identity services, raw runtime hoặc offline commands ở runtime; được import types, facade tokens và HTTP helpers. `authentication/services/` và migrations được dùng TypeORM trực tiếp. Với `src/modules/` (ADR 0031) rule chỉ áp cho `*.controller.ts`, `*.http-port.ts`, `*.module.ts`; service/repository/helper/declarations của module được dùng TypeORM và `ProductAuthorization`. `infrastructure/` ghép services; provision/migrate/bootstrap chỉ tools dùng. `apps/api/test/module-boundaries.spec.ts` kiểm bằng ESLint thật, gồm negative cases và Root bypass.
- Không route HTTP cho provisioning, manifest upload hay superadmin bypass; các việc đó là CLI trong `apps/api/tools/`.

## Hiện trạng

- Chọn value codecs duy nhất ở `authorization/product.manifest.ts#createProductAuthorizationCore` (Day.js timestamp + standard codecs); `ProductRuntime.create` và `apps/api/tools/product.ts` cùng gọi nó, release là `createProductRelease(core)` (không prepare lúc import).
- `ProductRuntime` wire bốn DB logins, privilege probe, application fence và manifest sync vào AppModule thật trước listen/readiness. API env `apps/api/.env.api` riêng; không migration/bootstrap/admin secret.
- Handler nhận port token của capability (`AUTHENTICATION_HTTP_PORT`, `ADMINISTRATION_HTTP_PORT`, `METRICS_SNAPSHOT`, `ReadinessGate`) chỉ gồm operations và HTTP config; không DataSource/manager/DB credentials, runner hay offline command. `ProductRuntime` là provider private của `RuntimeModule`; `apps/api/test/structure.spec.ts` kiểm DI thật và inventory route/OpenAPI.
- OIDC/session/2FA ở `authentication/services/` (chỉ Google, ADR 0027: không đăng nhập/mật khẩu/khôi phục local; env `AUTH_METHODS` làm boot fail); route thiếu classification làm boot fail. Guard ở `authorization/enforcement/` kiểm session sớm, service vẫn recheck trong fenced transaction.
- Mọi route khai báo dưới `/api` ngay trong `@Controller` (ADR 0019); callback OIDC trả 303 tới đích cố định: `/` hoặc `/login?error=oidc`. Binding được gọi bằng `binding_ref`, không trả subject. ADR 0027 §6–7 (migration `017`): mỗi tài khoản tối đa một binding đang bật (partial unique index), không link/unlink, không xác thực lại bằng Google (purpose attempt chỉ `login`/`activation`); callback OIDC không bao giờ đặt `reauthenticated_at`, `fresh` chỉ từ 2FA. ## Quy tắc khi sửa

- Khai báo quyền dùng hằng có kiểu, không dùng chuỗi trần (ADR 0016, mục "Quy ước hằng có kiểu"). Dạng duy nhất của repo là `as const` object cùng union dẫn xuất cùng tên (`export const EmployeeAction = { Read: 'read', ... } as const; export type EmployeeAction = (typeof EmployeeAction)[keyof typeof EmployeeAction]`), không dùng TypeScript `enum`: `node` chạy `tools/` và test bằng type stripping (enum báo lỗi cú pháp, đã thử với Node 24) và `tsconfig.test.json` bật `erasableSyntaxOnly`. Hằng nằm trong module sở hữu declarations, đặt tên `<module>-authorization.types.ts` (`modules/{permission,employee,team,work-request}/<module>-authorization.types.ts`, `modules/report/`, `modules/work-calendar/`, `administration/account-authorization.types.ts`, `document/`), import trực tiếp đuôi `.js`; validator `fresh@1` và obligation `audit@1` ở `authorization/product-capability.types.ts` (`ProductValidator.Fresh`, `ProductObligation.Audit`). Core (`authorization/core`) vẫn chỉ nhận `string`, không import các file này. Giá trị của hằng là chuỗi đã lưu trong manifest/DB/audit: không đổi giá trị (đổi hash release), chỉ thêm member. Thêm action mới: (1) thêm member vào enum của resource, (2) khai báo trong `actions` bằng `[EmployeeAction.X]: optionalAction(PermissionPolicy.Y)`, (3) thêm grant `grant(EmployeeResource.Employee, EmployeeAction.X, PermissionRole.Admin, EmployeeTemplate.AllEmployees)` trong `<module>.declarations.ts` (permission `resource.action` do `permissionKey` dựng; `grant` của module nhận `<Module>ActionOf`, sai action của resource khác là lỗi biên dịch), (4) dùng cùng hằng ở `@ProductAuthorize`/`ProductQuery`/`ProductCommand`, (5) release mới theo quy trình hiện có. `test/authorization-keys.spec.ts` ghim giá trị chuỗi của mọi hằng và kiểm tập action/policy/template/relation đã khai báo bằng đúng tập hằng. Tên field của resource (`code`, `state`), tên cột/bảng binding, giá trị `RequestState` và test cũ vẫn là chuỗi.
- File dưới `src/` tối đa 300 dòng không tính dòng trống/comment (ADR 0033, ESLint `max-lines`); miễn `*.declarations.ts`, `*.schema.ts`, `*.migration.ts`, `*.manifest.ts`. Ngoại lệ tạm (nền tảng: `product-mfa.service.ts`, `policy.validator.ts`, `product-authority.service.ts`) nằm trong `eslint.config.js`; xóa dòng tương ứng khi tách file, không thêm file mới vào danh sách. Service nghiệp vụ tách thành `*-read.repository.ts` (query), `*-command.repository.ts`/`*-effect.repository.ts` (ghi/effect), `*-database.helper.ts`/`*-facts.repository.ts`/`*-facts.helper.ts` (facts: phần async trong repository, SQL thuần dùng chung trong helper); `*.service.ts` giữ class và hàm tạo mảng command/query nhận repository; đăng ký ở `infrastructure/product-modules.factory.ts`. `*.helper.ts` dưới `src/` không dùng `async`/`await`/`Promise` (ESLint `no-restricted-syntax` trong `eslint.config.js`, kiểm bởi `test/helper-sync.spec.ts`); effect async thuộc repository/service.
- Mọi `*.repository.ts` là một class `XxxRepository` (ADR 0033 bổ sung 2026-10-22, người dùng chốt; thay quy ước "class chỉ khi có dependency thật" cho repository): `ProductCommand`/`ProductQuery` là field `readonly`, dependency qua constructor vào `#private`, `EntityManager` luôn truyền vào method (không giữ trong field), method không state vẫn là method instance (không `static`). Instance tạo ở composition root (`ProductRuntime.create`, `createProductModules()` trong `infrastructure/product-modules.factory.ts`, `tools/product.ts` cho `ProductAuditRepository`, test stack tự tạo) và truyền tường minh; không Nest DI, service locator hay singleton. Repository mới theo đúng dạng này. Ngoại lệ có chủ đích (ADR 0033, 2026-10-23): repository SQL không trạng thái chỉ dùng nội bộ một service hoặc migration (`ProductManifestReconciler` tạo 5 repository manifest, migration `012` và `product-root.service.ts` dùng `ProtectedStateRepository`) được tạo tại chỗ vì migration không có composition root.
- SQL chọn cột tường minh (ADR 0038): không `SELECT *`, `alias.*`, `RETURNING *`, whole-row JSON trong `src/`; `apps/api/test/explicit-columns.spec.ts` quét mã nguồn. `SELECT * FROM <cte>` chỉ hợp lệ khi CTE do chính file khai báo cột.
- Biến môi trường mới: thêm vào `config/app.config.ts` có validation và vào `apps/api/.env.example` (không giá trị thật).
- DTO có validation và Swagger examples; route khai báo success shape và mọi status thực tế. Không trả field ngoài projection, không phân biệt foreign/absent.
- Không log secret, token, cookie, authorization header hay PII.
- User admin không có capability reset/link/impersonate global identity.
- 2FA (ADR 0026): tài khoản có 2FA đã xác nhận chỉ nhận `fresh` từ `POST /api/auth/mfa/verify`; đường mới đặt `reauthenticated_at` phải gọi `hasConfirmedSecondFactor` và từ chối như lỗi xác thực. Phiên sau confirm/verify/gỡ là bản chép dòng phiên cũ (method, binding, assurance, `authenticated_at`, `expires_at`), chỉ đổi `reauthenticated_at` và `auth_epoch`; không dùng `createSession` (sẽ kéo dài hạn). `auth_epoch` do 2FA đổi chỉ qua trigger `mfa_epoch` (xác nhận, gỡ, reset, sai từ lần thứ 10); không tăng tay thêm. Mọi thao tác 2FA (kể cả reset offline) khóa dòng `app_user` (`FOR NO KEY UPDATE`) trước khi đọc/ghi bảng 2FA, nên tuần tự với nhau; confirm/verify khóa thêm `mfa_totp FOR UPDATE`. Secret chỉ ở response setup, mã khôi phục chỉ ở confirm/tạo lại; không log/audit mã, secret, `key_id` hay khóa. Khóa mã hóa chỉ ở env API, không ở ops env/DB/test artifact (fixture dùng khóa ngẫu nhiên mỗi lần chạy). Lỗi giải mã là lỗi server (503), không tính là sai mã. Reset 2FA chỉ là CLI offline có approval, không route HTTP.
- Đổi `app_user.email_canonical` hoặc `email_verified` phải tăng `auth_epoch` trong cùng UPDATE (phiên dựa vào epoch, không so lại email; ADR 0023 §4.2). Trigger `require_email_epoch` (migration 015) từ chối mọi login vi phạm; đường mới đổi email cần ADR. Gắn email Root là CLI offline `set-root-email`, không route HTTP.

- Feature module chỉ khai báo controllers; `AppModule` import `RuntimeModule.register(runtime)` vào từng feature module. Capability mới: thêm port token + bound operations trong `runtime.module.ts`, declaration fragment vào `authorization/product.manifest.ts`; không `@Global()`, không export `ProductRuntime`.
- Controller chỉ xử lý HTTP input/output và gọi operation đã định nghĩa; không đặt SQL, parsing scalar, policy algebra hoặc orchestration DB trong controller/filter. Không tạo service chỉ chuyển tiếp nếu không có trách nhiệm riêng.
- Chọn adapter và bind DI ở composition root. Module runtime giữ pool/config nhạy cảm private; feature chỉ inject facade/token có operations cần thiết. Không cast facade về runtime để lấy capability bị ẩn.
- Services import implementation trực tiếp; không thêm interface/repository abstraction chỉ để theo Clean Architecture. Core vẫn thuần và không biết tên domain hoặc Root.
- SQL chỉ parameterized, identifiers từ binding đã đăng ký; transaction chỉ dùng manager được truyền vào. Giữ DB clock/microseconds/collation, fence trước facts, audit/revision cùng commit; không network/hash mật khẩu trong fence.
- Migrations không đổi tên/timestamp/SQL đã áp dụng; thêm forward migration nếu cần semantics mới. Privilege/protection probes và negative tests phải khớp login/ACL/function/trigger thật; không gộp credentials.
- `ProductAuditOutbox` gửi ngoài transaction/fence, ack theo lease token và retry hữu hạn; chưa có sink thì không tự wire worker.
- Di chuyển file phải giữ route paths/status, cookie, CSRF, trusted proxy, projection, route classification và bootstrap ordering. Cập nhật imports/exports/tests/OpenAPI cùng task, không bỏ validation/error handling khi tách controller.
- Error filter dùng mapping lỗi có chủ đích; lỗi không biết trả lỗi server an toàn, không biến thành 200/allow hoặc lộ DB detail. Body lỗi là `{ statusCode, code }` với `code` từ `infrastructure/helpers/api-error.helper.ts#apiErrorCode` (theo status) hoặc, duy nhất, từ `ApiRejection` (tập đóng key→status, service ném sau khi authorize); `code` là key locale của web, quy tắc ở root `AGENTS.md` §Locale và mã lỗi. Giới hạn body/query/page size và validate trước khi gọi operation.
- Config mới phải fail boot nếu thiếu/sai và ảnh hưởng bảo mật; không default credential, permissive CORS/proxy hoặc fallback provider để app khởi động được. Không bật tính năng qua env khi semantics chưa được chốt.
- Mail/audit delivery không được coi là durable khi chỉ chạy promise nền; capability unavailable phải phản ánh đúng contract. Không thêm endpoint admin/debug để vượt provider hoặc xem secrets.

## Chạy

- `pnpm run start:dev` (build rồi chạy `apps/api/dist/main.js`, đọc `apps/api/.env.api` nếu có (root forwarding chạy với cwd API)).
- Smoke test: `pnpm run test:unit -- apps/api/test/workspace.smoke-spec.ts`.
- Route/OpenAPI inventory, DI boundary, bootstrap failure (không Docker): `pnpm run test:unit -- apps/api/test/structure.spec.ts`. Đổi route/facade có chủ ý thì sửa literal trong test cùng lý do.
- Integration (ADR 0034): `pnpm run test:integration` do `tools/test.ts` điều phối. Khi có file dùng `startModuleStack(` runner khởi MỘT container PostgreSQL cho cả lần chạy, dựng template `module_<digest>` một lần (provision + 13 migration nghiệp vụ + sync) rồi truyền qua env `HRM_TEST_PG`; mỗi file `startPostgres({ shared: true, template })` nhận database riêng (`CREATE DATABASE … TEMPLATE`, dọn `DROP DATABASE … WITH (FORCE)`). Mặc định `startPostgres()` vẫn là container riêng: file cần cluster riêng (role/cluster setting, kill session, migration từng bước, CLI offline, đo thời gian; `startModuleStack({ isolated: true })`) KHÔNG đặt `shared`. Role `product_*` là cấp cluster, tên cố định trong migration, nên mọi database của một cluster chung dùng chung bộ mật khẩu `TestPostgres.passwords`; query đếm session theo role phải lọc `datname = current_database()`. Chạy trực tiếp `node --test` (không runner) tự dựng container riêng.
- HTTP E2E: `pnpm run test:e2e -- apps/api/test/product.e2e-spec.ts` (cần Docker). Khi đổi routes/DI/auth, kiểm cả trường hợp unauthenticated, unauthorized, invalid input và response projection liên quan; không chỉ happy path.

## Tooling thuộc app

- API sở hữu `apps/api/test/`, `apps/api/tools/`, env/Compose và scripts/dependencies riêng trong `apps/api/package.json`. Root giữ orchestration và tooling/tests chung.
- Build chỉ emit source qua `tsconfig.build.json`; tests/tools kiểm thêm `tsconfig.test.json`. `tsconfig.json` bao phủ source/test/tools cho editor và ESLint project service.
- `apps/api/eslint.config.js` import baseline `eslint.shared.config.js` ở root và áp rules với path tương đối từ app; ESLint tìm config gần từng file.
- Env `.env.api`/`.env.ops` chỉ đọc trong app, không fallback về root hoặc trộn credentials runtime/ops.
- CLI activation artifacts tương đối resolve từ cwd API; ưu tiên absolute path tới vị trí riêng an toàn.
