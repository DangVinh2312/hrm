# @hrm/api-go

Bản Go/Gin của backend, chuyển dần theo [ADR-20](../../docs/decisions/ADR-20-go-gin-backend-migration.md); Go là nguồn duy nhất, không so byte với NestJS ([ADR-22](../../docs/decisions/ADR-22-go-owns-the-contract.md)). Đọc root `AGENTS.md` trước; bất biến bảo mật ở đó áp dụng nguyên văn. Hiện có `cmd/api`, `cmd/hrmctl` (`provision`, `migrate`, `sync`), `contract` (file contract nhúng vào binary), `internal/app` (thứ tự boot, shutdown), `internal/config`, `internal/database`, `internal/offline`, `internal/apperror`, `internal/authorization/enforcement`, `internal/authorization/core` (lõi quyết định thuần, chưa route nào dùng), `internal/authorization/values` (codec giá trị), `internal/authorization/compiler` (biên dịch plan thành predicate SQL), `internal/authorization/gateway` (gateway đọc dữ liệu theo plan), `internal/authorization/keys`, `internal/authorization/declarations`, `internal/authorization/manifest`, `internal/modules/permission`, `internal/httpapi` (engine, lớp giao thức, lỗi, cookie/CSRF, `DecodeCommand`, `DecodeEmptyCommand`, `ClientIP`, proxy, inventory, route `auth/csrf`, `auth/options`), `internal/authentication` (session, limiter, MFA, OIDC, 11 route `auth/*`), `internal/audit`, `internal/health`, `internal/openapi`. Route phục vụ tại Go nằm ở `httpapi.MigratedRoutes`; route còn lại proxy sang NestJS qua `API_UPSTREAM_URL`.

Contract do Go sở hữu và sửa tay: `contract/*.json` (route, OpenAPI, mã lỗi, privilege), `contract/route-ownership.md`, `contract/test-port-tracker.md` (checklist port test TypeScript), `internal/database/migrations/*.sql` (trước release đầu được sửa và dựng lại database local), `internal/database/privilege_declarations.go` (sửa cùng migration đổi ACL, hàm, trigger). `release.json`, `bindings.json` chỉ là tham chiếu cho declarations ở F5. `contract/package-dag.md` là nguồn cấu trúc package, đổi cạnh phải sửa khối ở mục 4 của nó.

`internal/authorization/authority` ghép session/facts đã xác minh với plan và effect trong fenced transaction. Query/command được đăng ký lúc composition, kiểm đúng pointer và không nhận bản sao; handler chỉ nhận facade đã bind. Lớp route `authorize` kiểm permission có trong declarations lúc boot; guard sớm vẫn chỉ kiểm shape cookie, engine kiểm session và quyền thật. `test/unrestricted_boundary_test.go` kiểm AST để giới hạn `PlanUnrestricted` trong core/authority.

## Lệnh

```sh
cd apps/api-go
go vet ./...
go tool golangci-lint run
go test -race ./...
go build ./...
```

Từ root: `pnpm --filter @hrm/api-go run build | test:unit | test:integration | lint`. Build ghi vào `dist/`. Không cài CLI global; thêm thư viện ở task dùng đầu tiên, ghim trong `go.mod`.

Integration đặt sau build tag `integration`, file `*_integration_test.go`, cần Docker: `go test -tags integration ./internal/database`, `go test -tags integration ./internal/offline`, `go test -tags integration ./internal/audit`, `go test -tags integration ./internal/authentication/...`, `go test -tags integration ./internal/authorization/gateway`, mỗi package một lần. `test.NewDatabase` dựng template bằng CLI TypeScript cho provision/migrate, Go cho manifest sync và bốn anchors; Root còn dùng CLI TypeScript tới Task 17, nên cần `apps/api/dist` đã build. Test cần database có facts code-owned, nhân viên, tài khoản, session, Root dùng `test.NewDatabase` và `test/fixture` (`go test -tags integration ./test/...`). Chạy trực tiếp `go test` thì phải chạy `pnpm --filter @hrm/api run build` trước; `test:integration` của package này tự build, còn template từ chối `dist` cũ hơn một file `apps/api/src` (so với `dist/tsconfig.tsbuildinfo`). Mỗi binary test một container, reaper của testcontainers dọn khi process kết thúc. `.golangci.yml` bật tag này, nên `golangci-lint run` đọc cả test integration; `go vet` thì không, chạy thêm `go vet -tags integration ./...`.

Route phục vụ tại Go chỉ thêm bằng `httpapi.Register`, route còn proxy bằng `httpapi.RegisterProxied`, hàm này nhận `*Upstream` chứ không nhận handler vì `CheckInventory` không so class của route proxy; wrapper `guarded` chạy `Classification.Check` trước handler; `httpapi.CheckRoutes` từ chối route có handler cuối khác wrapper đó và `internal/app` gọi nó lúc boot, vì `forbidigo` không bắt method Gin được promote qua struct của mình (`server{engine}.GET`). `CheckRoutes` so tên closure qua `FuncForPC`. Đo trên Go 1.27.3, tên giữ nguyên `guarded.func1` kể cả khi `guarded` được inline, với `-race`, `-cover`, `-gcflags=all=-l`, `-gcflags=-l=4`; `guarded` vẫn để `//go:noinline` vì tên này là chi tiết của compiler. `CheckRoutes` tính tên cần so từ chính `guarded` lúc chạy, nên đổi đồng loạt vẫn khớp; chỉ khi một nơi gọi có tên khác thì route đó bị từ chối lúc boot. `forbidigo` cũng cấm `http.Request.Body`, `Form`, `PostForm`, `MultipartForm`, `ParseForm`, `ParseMultipartForm`, `FormValue`, `PostFormValue`, `FormFile`, `MultipartReader`, `Write`, `WriteProxy` và `httputil.DumpRequest`, `DumpRequestOut` (đọc body không qua `httpapi.DecodeCommand`) ngoài `body.go` và test; proxy không cần miễn trừ vì `ReverseProxy` tự đọc body; không bắt khi promote qua struct nhúng `*http.Request`, nên không nhúng kiểu này. Giới hạn còn lại, cả `CheckRoutes` lẫn `forbidigo` đều không bắt: `NoRoute`, `NoMethod` gọi qua struct của mình (`server{engine}.NoRoute(h)`), và `Use`, `Group(path, raw)`, là middleware chạy trước guard; `http.Handler` khác truyền vào `NewServer` thì bỏ qua cả engine. Các chỗ này dựa vào review. Rule theo file (handler, credential) nằm ở `imports_test.go` vì Go không có import chỉ kiểu và handler cùng package với repository. Giới hạn của `checkHandlerTypes`: interface do composition root inject vào handler không phát hiện được bằng phân tích tĩnh; `var Revoke = R.Revoke` hay field kiểu func ở file repository là facade, được phép; `type D database.Runner`, `type S database.Store` có field hay method khai ở package cấm thì handler không được dùng cả giá trị, vì chuyển sang struct không tên hoặc interface sẽ mở lại đúng field và method đó; handler cần kiểu thì repository tự khai field của nó (field riêng giữ runner vẫn được, `type Row gateway.Row` khi `gateway.Row` rỗng vẫn được). `rowserrcheck` khai `pgx/v5` và đã kiểm ca âm trên pgx thật: bắt thiếu `rows.Err()`. `sqlclosecheck` không enforce thiếu `rows.Close()` trên `pgx.Rows` (ADR-20 §8); bảo vệ thật là runner: rows còn mở làm commit lỗi. `forbidigo` đã kiểm ca âm trên Gin v1.12.0 thật, kể cả import đổi tên và method value `c.ClientIP`; không bắt method được promote qua struct nhúng `*gin.Context` (`w.ClientIP()`), nên không nhúng `gin.Context`. Chưa kiểm thì chưa coi là được enforce. Mặc định golangci ẩn bớt: `max-same-issues` 3, `uniq-by-line`; khi cần xem đủ thì thêm `--max-same-issues 0 --max-issues-per-linter 0 --uniq-by-line=false`.

## Dữ liệu và text

- Body JSON: route ghi có body gọi `httpapi.DecodeCommand[T](c, origin)` vào struct của route, không `[]any`, `map[string]any`, không `ShouldBind*`. Hàm này kiểm CSRF trước rồi mới đọc body: thiếu CSRF kèm body hỏng là 403. `decodeJSON` không export, vì `routes.json` không biết CSRF nên không gì khác bắt được route ghi quên nó. Route POST hay DELETE bỏ qua body chỉ gọi `EnforceCSRF`; route không nhận field nào nhưng từ chối member lạ gọi `DecodeEmptyCommand` (không body hoặc `{}`). Mọi route ghi đã chuyển bị `TestEveryMigratedWriteRefusesAMissingCSRF` (`internal/app`) duyệt từ `MigratedRoutes`. `encoding/json/v2` với `RejectUnknownMembers` từ chối member lạ, khác hoa thường, lặp (kể cả lặp qua escape), UTF-8 sai, surrogate đơn lẻ, số tràn kiểu đích (ADR-21). Thiếu field và `null` ở field struct đều ra giá trị zero, không lỗi: field bắt buộc phải được route validate, cần phân biệt thì dùng con trỏ; cần phân biệt cả `null` với thiếu thì dùng kiểu có `UnmarshalJSON` (`authentication.bodyText`).
- Khi port một route có body: member lạ là 400, nên đối chiếu struct với body mà `apps/web/src` thực sự gửi. `\u0000` là JSON hợp lệ nên đi vào string: port `inputText` phải từ chối nó, nếu không PostgreSQL báo lỗi và client nhận 503 thay vì 400.
- Hash và giá trị lưu: struct Go với `encoding/json`, thứ tự field theo khai báo struct.
- Text: email đăng nhập chỉ ASCII (ADR-21), nên `strings.ToLower` đủ. Giới hạn độ dài đếm rune như `char_length` của PostgreSQL. Thứ tự hiển thị chữ có dấu dùng `x/text/collate`.

## `database`

- `database.Run` là đường duy nhất tới transaction. `Tx` không nhận context, nên context của request không hủy được mutation giữa chừng; callback nhận context có deadline riêng và giữ value của caller. Callback chạy lại khi retry, nên không có effect ngoài `Tx`. `Tx` chết sau callback; dùng `Tx` trong `go` bị `checkTxInGoroutine` từ chối.
- Mode `outbox` chỉ dùng login `outbox` cho claim/ack delivery, không lấy application fence, không revision, không metric chờ/giữ fence, không `Serialize` và không `audit.Append`. Vẫn qua `database.Run` với timeout/retry/commit/lifetime hữu hạn; không fallback sang bốn pool của API. Sink chạy ngoài transaction, worker chưa được wire khi chưa có sink thật (ADR-07).
- Exec mode là `QueryExecModeExec` (ADR-20 §6): tham số gửi dạng text, OID 0, kiểu do PostgreSQL suy như `pg`. Riêng `[]byte` đi dạng text `\x…` OID 0, chỉ tương đương `pg` khi đích là `bytea`: chỉ dùng `[]byte` cho tham số `bytea`. Giá trị jsonb truyền chuỗi, không truyền map. Nhiều statement chỉ qua `Tx.Exec` không tham số, vì nó dùng simple protocol; `Tx.Query` không có.
- Đọc nhiều dòng bằng `pgx.CollectRows`. `pgx.ForEachRow` làm `rowserrcheck` báo nhầm. Không cần `QueryRow` ở `Tx`.
- `pgx` trả lỗi khi commit một transaction đã hỏng; `pg` qua TypeORM coi là thành công. Bản Go chặt hơn: không báo commit khi server đã rollback.
- Context hết hạn giữa câu lệnh thì pgx đóng connection bất đồng bộ: gửi `CancelRequest` qua connection mới và chờ server tối đa 15 giây (`asyncClose`). Runner vẫn trả đúng hạn, nhưng `pool.Close` chờ phần dọn này; test giả server treo bằng `WireProxy.Hold` phải `Release` trước khi đóng pool.
- Mọi lỗi cần log chỉ lấy `SQLSTATE` và kiểu lỗi. Lỗi của `url.Parse` chứa cả URL và password, goose có thể kèm câu SQL. `UnavailableError`, `ConflictError` chỉ giữ code.
- Goose bỏ dòng trống và dòng comment đứng đầu mỗi statement và `TrimSpace` hai đầu; thân hàm nằm giữa statement nên `prosrc` không đổi, so catalog đã xác nhận. Goose không được xuất hiện trong `cmd/api` (`TestGooseIsOnlyInTheOfflineCommand`), vì vậy nó chỉ được import ở `internal/offline`.
- Trong test fixture, `SET session_replication_role=replica` bỏ qua trigger, chỉ dùng bằng superuser của cluster tạm.
- `CREATE DATABASE … TEMPLATE` không chép ACL của database: bản sao lại cho `PUBLIC` quyền `TEMP` và probe từ chối. `test.NewDatabase` chạy lại `REVOKE TEMP` của provision trên bản sao.

## Bẫy của Go và Gin

- JSON ra: `encoding/json` v1 cho slice nil thành `null` và escape `<>&`, U+2028/9; v2 cho slice nil thành `[]`. Chọn một và test shape.
- Số: giữ `::text` trong SQL, kiểu chuỗi cho `int8`, `numeric` lớn; không đi qua `float64`.
- Regex: RE2 không có lookaround.
- Header: đọc `Header.Values`; `Origin`, `X-Csrf-Token` lặp thì từ chối, cookie của app lặp thì 400. Query string: chưa có helper vì route đã chuyển không đọc query; route đầu tiên đọc query phải viết helper từ chối key lặp, key lạ. Ngoại lệ: callback OIDC, vì IdP có thể gửi thêm tham số; `OidcService.Callback` chỉ từ chối lặp với `state`, `code`, `error`, `iss`, nhận key khác kể cả lặp, nhưng query sai cú pháp ở bất kỳ key nào vẫn bị từ chối (`url.ParseQuery`).
- HTTP: đặt `MaxHeaderBytes`, `ReadHeaderTimeout`, `IdleTimeout`, `MaxBytesReader`; tắt `RedirectTrailingSlash`, `RedirectFixedPath`; IP client tự tính theo `TRUST_PROXY` (`httpapi.ClientIP`: `net/netip`, giá trị ở vị trí tin cậy không phải địa chỉ thì dùng IP socket, mỗi địa chỉ một cách viết, bỏ `::ffff:` và zone).
- Lớp giao thức do `net/http` xử lý trước handler: escape sai ở request line nhận `400 text/plain`, `Content-Length` lặp giống nhau được gộp, `Transfer-Encoding` cạnh `Content-Length` được xử lý chunked mà không đóng connection. POST rỗng dạng chunked không `Content-Type` ở route `DecodeEmptyCommand` nhận 400, vì `ContentLength` là -1; web gửi `Content-Length: 0`. Reverse proxy khi deploy phải chuẩn hóa framing (ADR-22).
- Đường dẫn: khớp chính xác, chữ hoa và `/` cuối là 404. `engine.UseRawPath` để `%68ealth` không khớp `health` và `a%2Fb` nằm trong một param. Gin giải mã param của raw path như query (`+` thành dấu cách), nên `NewHandler` đổi `+` thành `%2B` trong `RawPath`. GET tự có HEAD trong `Register`. Gin ưu tiên static segment hơn param (`/api/hr/employees/me` trước `:id`).
- Proxy: `ReverseProxy` thêm vào header đã đặt chứ không thay, nên `Upstream.Handle` gỡ header bảo mật trước khi forward và đặt lại khi lỗi. Target đi nguyên văn qua `URL.Opaque` từ `RequestURI`. Idle của transport phải dưới `keepAliveTimeout` 5 s của Node.
- Thời gian: định dạng do SQL hoặc codec, nhúng `time/tzdata`, không lấy timezone máy; đồng hồ có thẩm quyền là DB.
- Hủy request: runner dùng `context.WithoutCancel` cộng deadline riêng; panic trả `503 error.unavailable`, giữ `http.ErrAbortHandler`.
- testcontainers: `ForAll(...).WithDeadline` chỉ chặn trên, mỗi strategy vẫn dừng ở mặc định 60 s của nó; đặt `WithStartupTimeout` trên từng strategy. `OpenPools` cho mỗi login 2 s: máy tải cao có thể hết hạn trước khi PostgreSQL trả lời, `test.NewDatabase` chờ lại có giới hạn và `test.Redact` giữ `UnavailableError.Code` (`deadline` là server không trả lời kịp, `connection` là không kết nối được, SQLSTATE là server từ chối).
- OIDC (`go-oidc` v3.21.0): ghim `SupportedSigningAlgs` RS256 (test RS512 ký thật bằng key của IdP mới bắt được khi nới); `SkipExpiryCheck` bỏ cả `nbf`, và thư viện không kiểm `iat`, `azp`, `nonce`, nên `checkIDTokenClaims` tự kiểm theo `oauth4webapi` (lệch 30 s). Issuer so khớp nguyên văn ở `NewProvider`, `RemoteKeySet` tải key bằng context lúc tạo (`oidc.ClientContext`), không theo request. `oauth2` gửi `client_secret` trong body chỉ khi khác rỗng. HTTP client của provider không theo redirect và giới hạn body 1 MiB, vì `go-oidc` đọc discovery và JWKS bằng `io.ReadAll`. Discovery chạy lúc boot (`internal/app`, bước `oidc providers`), IdP không trả lời thì không listen. CA riêng cho Go đặt bằng `SSL_CERT_FILE` (từ Go 1.27 có hiệu lực cả trên macOS). Trên macOS biến này bỏ trust store hệ thống nên chỉ còn CA đó; trên Linux nó chỉ thay file mặc định, `loadOnDiskRoots` vẫn đọc thư mục như `/etc/ssl/certs` trừ khi đặt `SSL_CERT_DIR` (`crypto/x509/root.go`). `Provider.Claims`, `IDToken.Claims` giải mã bằng `encoding/json` v1 (tên không phân biệt hoa thường, key lặp lấy giá trị cuối): nhận document thô qua `rawPayload` rồi đọc lại bằng v2. Vì vậy `Provider.Endpoint()` không được dùng: `TOKEN_ENDPOINT` viết hoa đặt sau `token_endpoint` sẽ đổi token URL sang host khác; `oauth2.Endpoint` dựng từ `metadata` đọc bằng v2. XLSX: chuỗi `=` không thành công thức, kiểm chuỗi rất dài.
- AST đóng bằng interface có method chưa export vẫn bị thỏa mãn từ package khác qua struct nhúng (`struct{ core.ConstantExpr }`) và qua con trỏ (`&core.ConstantExpr{}`), nên mọi `switch` theo kiểu trên `Expr`, `PlanExpr`, `gateway.Filter` phải có nhánh từ chối. `Expr` có thể chứa chính nó qua slice, nên duyệt biểu thức chưa validate phải có giới hạn node. Không `recover` được stack overflow.
- `depguard` tính cả file `_test.go`: rule `authorization-core` khai `!$test`, vì `core_test` import `core` và `values`, như fixture TypeScript. Ranh giới của code thật vẫn do `depguard` và `TestRealImportsFollowTheDAG` giữ. `$gostd` cho qua cả `net/http`, `os`, nên rule liệt kê `net`, `database/sql`, `os`, `crypto`, `syscall`, `log`, `io/ioutil` ở `deny`; đã kiểm bằng probe.
- `encoding/json` v1 đổi UTF-8 sai thành U+FFFD mà không báo lỗi, nên hai giá trị khác nhau có cùng canonical. Text tự do đi vào hash phải qua `utf8.ValidString` trước (`Core.Validate` làm việc này cho declarations; `manifest.Prepare` làm tương tự cho grant parameters qua value codecs và kiểm role labels trước hash).
- Test có ký tự ngoài ASCII: công cụ Write/Edit của agent giải mã chuỗi escape Unicode bốn chữ số hex trong tham số thành ký tự thật, nên test chứa ký tự gần giống (Kelvin, chữ toàn độ rộng) mất ý nghĩa mà không báo. Viết ký tự bằng `string(rune(0x212a))`, rồi kiểm file chỉ ASCII bằng `LC_ALL=C grep -n '[^ -~\t]'`.
- Advisory lock của `RunOptions.Serialize` cũng chịu `lock_timeout` (tối đa 1 s) và retry của runner: test giữ khóa này phải nhả trong khoảng đó, nếu không bên chờ nhận `ConflictError` chứ không bị chặn.

## Manifest

- `declarations.Source()` và `Bindings()` tạo literal structs mới mỗi lần; chỉ composition root và tests import package này. `NewCore()` chọn codecs, `RuntimeCapabilities()` khai implementation có sẵn độc lập với source release.
- `manifest.NewReconciler(runner, core, capabilities)` clone capabilities; `Reconcile(ctx, reconciler, release)` chỉ nhận release do cùng core prepare. Field của Release/Reconciler giữ private.
- `contract/manifest-readiness.json` là bridge tạm cho NestJS upstream; test Go ghim sequence/hash theo Prepare. NestJS không reconcile khi boot; TypeScript CLI sync chỉ dùng trong tests lịch sử.
- `ProtectedStateHash` giữ raw JSON number khi đọc PostgreSQL. Không decode catalog vào `float64`: materialized hash phải được Go và TypeScript đọc chéo tới cutover.
