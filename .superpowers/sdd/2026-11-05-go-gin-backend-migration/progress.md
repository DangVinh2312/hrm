## Rulings

- Ruling 1: không commit, không worktree; làm trực tiếp trên working tree. Review package tạo từ một shadow git riêng trong workspace này — người dùng cấm commit và working tree có thay đổi chưa commit mà exporter phải đọc — nếu sai: chỉ tốn công đổi cách đóng gói diff.

- Ruling 3: T1 làm luôn phần bắt SQL migration và ghi `internal/database/migrations/*.sql`; T2 kiểm trên database thật — ADR-20 §3 liệt kê SQL là output của exporter, go-contract.spec kiểm khớp từ đầu — nếu sai: có vài file SQL chưa dùng tới T2.
- Ruling 4: `cmd/api/main.go` chỉ in lỗi ra stderr và exit 1 (fail closed), `go.mod` chỉ có `tool` golangci-lint; thư viện thêm ở task dùng đầu tiên, đối chiếu danh sách phiên bản của plan — tránh placeholder và dep treo — nếu sai: thêm dòng `go get` ở T2.
- Ruling 5: kiểm độ nhạy bằng bản sao file: sao lưu vào workspace, sửa, thấy đỏ, chép lại, so SHA-256; cấm `git restore`/`checkout`/`stash` — tránh mất thay đổi của người dùng — nếu sai: không có.
- Ruling 6: cho phép sửa `.prettierignore` (bỏ qua JSON/SQL sinh ra) và `docker/Dockerfile` (COPY package.json mới), dù ngoài danh sách Files — thiếu thì `format:check` và `pnpm install` trong Docker hỏng — nếu sai: hai dòng dễ hoàn tác.
- Ruling 7: module Go đặt tên `hrm/api-go` — repo không publish, ADR không nêu — nếu sai: đổi một dòng và import nội bộ.
- Ruling 8: chia T1 thành ba lượt nối tiếp: DAG, exporter, Go. DAG làm trước vì đây là điểm dừng hỏi người dùng — tránh dựng rồi bỏ — nếu sai: thêm một lượt dispatch.
